# Measured results (v1)

Deterministic stub-agent evaluation: **18 runs** (12 clean + 6 single-fault),
generated by `harness run-eval`. Regenerate with:

```bash
PYTHONPATH=src python -m harness.cli.main run-eval
PYTHONPATH=src python -m harness.cli.main verify-results
```

`verify-results` re-verifies every decision log's SHA-256 hash chain, replays
every run against a fresh engine (comparing state, attempt, and decision
digests record-by-record), and recomputes the metrics from the run table —
failing on any divergence.

## Method notes

- **Agent**: deterministic stub suite only (`adapter_id: "stub"`).
- **Checkpoints**: a scripted policy auto-approved the plan and merge
  checkpoints (standing in for the human); 36 checkpoints resolved, 0
  overridden. Override/deny paths are covered by integration tests, not by
  these numbers.
- **Faults**: explicit single-fault transforms applied by the harness after
  the first implement step; no multi-fault variants in v1.
- **First-pass** means the gate passed on its first invocation of the run.

## Files

- `metrics.json` — the four metrics plus metadata (single implementation:
  `harness/evals/metrics.py`).
- `run_table.json` — the normalized per-run table (18 rows).
- `manifest.json` — run IDs, scenarios, and decision-log digests.
- Per-run decision logs and isolated workspaces live under `runs/` (not
  committed; reproducible via `run-eval`).
